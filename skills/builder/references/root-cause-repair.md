# 根因修复

只在故障机制不清、同类失败再次出现、修复明显只压症状，或 Reviewer 指出因果链错误时读取。

## 证据链

1. 写清实际观察到的失败，不把时间吻合、报错末行或猜测当根因。
2. 列出能支持与排除候选机制的日志、状态、调用路径或最小复现。
3. 证据不能区分候选机制时，先补观测或做单变量试验；不要先扩大超时、重试、兜底或捕获范围。

## 最小修复

- 改动落在产生错误事实的最早可控边界，并保持现有恢复、兼容和失败语义。
- 回归判据必须在同一输入下让修复前失败、修复后通过；只证明“现在能跑”不够。
- 发现需要改变冻结行为、验收标准或 ownership 时停止当前 run，进入新方案。

## 停止条件

- 一次修复后同类 failure fingerprint 仍出现：重新诊断，不叠第二层补丁。
- 三个不同候选出现同类失败：按 runtime 的架构停止处理，交还用户。
- 关键证据不可获得且继续修改会扩大影响面：保留现场并停止。
