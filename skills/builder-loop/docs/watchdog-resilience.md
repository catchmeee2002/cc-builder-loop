# CC 长任务断线恢复方案（待定）

> 状态：**搁置** — 方案不够优美，先记录思路，不实施。
> 日期：2026-04-23

## 问题

CC 跑 builder-loop 长任务时，网络抖动或单次输出过长会导致任务中断。
tmux 解决了 SSH 断连，Stop Hook 解决了正常停止后续接，但仍有盲区。

## 现有防护层及覆盖范围

| 层 | 工具 | 解决什么 |
|----|------|---------|
| 终端保持 | tmux | SSH 断连 |
| 迭代续接 | Stop Hook (builder-loop) | CC 正常完成一轮后自动继续 |
| **缺失** | 无 | CC 进程崩溃 / API 中途断流 / CC hang |

## 方案思路：cc-guard.sh watchdog

tmux 内套一个 wrapper 脚本，CC 异常退出后带退避重试。

### 核心逻辑

- CC exit 0 → 正常退出，不重启
- CC 活了 >60s 才挂 → 大概率网络抖动，5s 后 resume
- CC <60s 就挂 → 可能是环境/认证问题，指数退避（30s→120s→300s）
- 连续 3 次秒退 → 放弃，tmux 弹通知

### 场景分析

| 场景 | 自动恢复？ | 用户需介入？ | 损失 |
|------|-----------|-------------|------|
| 短暂网络抖动 | ✅ CC 内置重试 | 否 | 无 |
| 网络断 30s+ | ✅ watchdog resume | 否 | 少量重复 token |
| 网络长时间断 | ❌ 放弃后不续 | 需手动拉起 | 任务搁置 |
| OOM 反复 crash | ❌ 无限重启 | 需手动杀 | 持续烧 token |
| 认证失败 | ❌ 正确放弃 | 需修认证 | 3 分钟 |
| Write 被拦循环 | 看早停配置 | 可能需介入 | 慢性失血 |
| CC hang 不退出 | ❌ 完全盲区 | 需人发现 | 时间浪费 |
| 多窗口 resume 串台 | ❌ | 可能搞破坏 | 文件被误改 |

## 未解决的 3 个洞

### 1. OOM / 慢死循环

每次活过 60s 但总会挂 → watchdog 永远认为"值得重试" → 无限循环。
需要：累计重启次数衰减，或跟踪总重启数设上限。

### 2. CC hang（进程活着但不工作）

CC 执行的 Bash 命令 hang 住（等网络/锁）→ 进程不退出 → watchdog/Stop Hook/Cron 全部盲区。
需要：外部超时监控（如检测 transcript 文件最后修改时间）。

### 3. 多窗口 resume 串台

`claude --resume` 无法指定 session ID → 可能恢复到错误会话 → 有破坏性。
需要：CC 支持 `--resume <session-id>`，或从状态文件提取 session ID。

## 相关背景

- Ralph Loop（放羊大叔插件）和 builder-loop 共用 Stop Hook 机制，但 Stop Hook 只在 CC 正常到达"停止"状态时触发
- Cron 心跳（CC 内置 CronCreate）在 REPL idle 时触发，但 API 不通时注入 prompt 也没用，且污染上下文
- 这套方案"能用但不优美"，三个洞任意一个误触都会造成 token 浪费或文件破坏
