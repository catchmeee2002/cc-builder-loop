# Builder Loop 文档政策

## 先判断是否触及文档面

只有改动影响对外行为、契约、导航、新增对外文件或架构决策时才更新文档。否则不做
找补式修改，并在审查证据中记录“未触及文档面”。

## 内容归宿

| 内容 | 归宿 |
|---|---|
| 仓库导航、长期协作约束、可复制命令 | `AGENTS.md` |
| 系统边界、稳定设计决策及理由 | `docs/architecture.md` 或设计文档 |
| 用户入口、安装、配置和对外行为 | `README.md` |
| 已交付历史 | `CHANGELOG.md` 和 Git 历史 |
| 可复现故障、环境限制、调试线索 | `docs/known-issues.md` 或对应问题文档 |
| 当前运行状态、测试结果、agent id、commit HEAD | ledger、JSON/JSONL 或自动报告 |
| API 字段、JSON schema、函数签名 | 代码、docstring 或 schema 文件 |

不要把同一事实复制进多个容器。详细内容已有稳定归宿时，其他文档只保留入口链接。

## 新鲜度与保质期

架构决策和外部契约无需保质期。会漂移的快照、调试记录或临时决策如果必须进入 Markdown，
节首写：

```text
[保质期: <事件或日期>, owner: <name>, 正向归宿: <结构化路径或长期文档>]
```

没有保质期的快照可在审计时删除。进展和当前状态采用覆写，不把历史持续 append 到当前态。

## 写法与审计

- 写可复用的“条件 → 动作”触发器，不写一次性事故叙事。
- 能从配置、schema、ledger、Git 或自动报告恢复的信息，不再手写一份当前快照。
- 修改后检查本地链接、命令、文件名和行为描述是否仍有效。
- Builder 负责写文档；Reviewer 独立判断是否该写、写到哪里、是否与代码和计划一致。
- 文档政策不可读取时停止 Phase D，不自行发明替代规则。
