# cc-builder-loop 设计哲学

> 本项目是 LLM 驱动的发散系统——Claude Code 的行为不确定，中间件层（hook / prompt / state / subagent）互相耦合，打补丁会滚雪球。以下原则是所有设计决策的判据。
> 原则零是项目的正向定位（在生态里占什么位），原则一至六是防御发散的约束，原则七约束本仓库自身。

## 零、独立判据编排器（项目定位）

本项目在 AI 协作生态里占的位是：**为自动化系统提供独立于被审计者的 ground truth 锚点**。

判据可信度的关键属性是**独立性**（定义者和执行者都独立于被审计者），不是"机器跑的还是 LLM 跑的"。机器判据是独立判据的最强特例（定义来自人、执行来自机器，与 LLM 系统零耦合），但不是唯一形态。

**LLM 判官越强，越需要独立锚点防止它飘。** 本项目不跟 LLM 判据竞争，而是做它的地基——把能用独立判据覆盖的部分钉死成 ground truth，让上层判断有一个说服不了的参照。

## 一、判据按独立性分层

判据是一条**独立性谱系**，按定义者和执行者与被审计者的隔离程度排列。三层覆盖不同类的错误，互不取代。

- **纯机器判据**（测试通过 / 文件存在 / exit code）：人定义 + 机器执行。最强独立性——可证伪、零成本重放、不可被说服。做 **ground truth 地基**——必要条件 / 硬门禁 / 防作弊兜底。
- **独立 agent 判据**（独立 tester subagent 执行 + 独立 planner 定义的用例）：独立 LLM 定义 + 独立 LLM 执行。独立性来自 subagent 架构天然属性——独立推理实例、独立上下文、可用不同模型，不与 builder 共享思维链。不依赖外部隔离机制（hook / 锁 / 读拦截）强制。定义者和执行者都不是被审计者，同源偏差被结构性打破。
- **同会话 LLM 判据**（reviewer / judge / 对抗验证）：覆盖机器和独立 agent 都测不到的语义——可读性、架构合理性、需求是否被满足。最弱独立性——LLM 判 LLM 有同源偏差，必须用对抗验证 / 多 lens 降偏，**不单票放行**。

**分层规则**：能用更高独立性判据覆盖的层，高独立性优先且兜底；只有独立性更高的层覆盖不了时，才下放到低独立性层，且必须降偏。

## 二、每份数据有且只有一个家

同一个事实不存两个地方。需要某个信息就去它的唯一源头读，不在消费侧缓存副本。冗余必漂移，漂移必出事。

## 三、显式授权，默认拒绝

不认识的东西不碰。不是我的 loop 不操作，不是我请求的 dirty 不带进来。写边界由 subagent prompt 职责声明 + merge 前 diff 审查 + PASS_CMD 兜底，不依赖按身份拦截的 hook 机制（该机制因 CC 内核不提供可靠的 subagent 身份信息已退役）。宁可多一步显式声明，不省一步引入隐式耦合。

## 四、改输入条件，不改输出约束

行为不对时，改数据结构和架构让正确行为自然发生，不在末端加特判堆约束。约束堆得越多系统越脆，因为每个约束都是一个"LLM 可能不遵守"的点。

## 五、同一个问题出现三次就是架构缺陷

单点修复只治标。同一模式的 bug 反复出现说明缺一层抽象或一道边界。找到共同根因，一次修掉。

## 六、契约先于实现

每个可执行单元（hook / 脚本 / subagent）先定义它的输入、输出和副作用契约，再写实现。测试验证契约是否被遵守，不验证实现细节。实现可以随时换，契约不能随便变。

## 附、为什么不追求超长 loop

本项目优化的是**单任务闭环的深度和稳定性**（1-3 小时），不追求 10 小时+的超长无人值守。

超长 loop 的适用前提——任务独立(互不依赖)、进度单调(只增不退)、无设计决策(只做实现)——只在**从零建项目 / 大规模机械迁移 / 测试批量补全**时成立。一旦项目进入功能迭代(新功能→bug→架构调整),每个任务依赖对既有代码的深度理解、任务间有因果链、架构决策需要人的判断——这些特征与超长 loop 的前提结构性冲突。

正确的真北是**单位时间内高质量交付的 loop 数量**,不是单个 loop 的运行时长。

## 七、本项目自身也受这些原则约束（dogfooding）

以上原则不只约束被构建的系统，也约束本仓库自身的文档与代码。

本文档曾出现六条原则同时存在于三处（`design-philosophy.md` / `CLAUDE.md` / `README.md`）——**这是原则二的违反点**：哲学文档自己没遵守哲学。发现即收敛：哲学正文只有这一个家，`CLAUDE.md` / `README.md` 只留导航指针。

落地约束：
- **文档放置按使用频率分层**——每轮都要遵守的操作规则进根 `CLAUDE.md`（CC 每轮自动加载），做架构决策时才查的判据进独立文档（按需读）。哲学属后者。
- 任何"为了方便再抄一份"的冲动，都是原则二的违反点，用指针代替复制。
